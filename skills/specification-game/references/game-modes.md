# Game modes

These formats specialize the shared rules in SKILL.md. Mode names are controls
only when requested by the player outside the objective text. Default to DOOM.

## DOOM

Use the core response, usually 180–300 words. Give the optimizer a specific
interpretation and one memorable consequence. Humor should target the absurd
metric or bureaucracy, not people harmed. A punchline is welcome; unsupported
certainty is not. Fold assumptions into the story or plausibility label. If
extinction needs invented global powers, say so or tell a smaller story.

## RESEARCH

Usually 350–650 words, or less if the finding is simple. Present:

- **Specification:** literal target, intended benefit, assumed or stated proxy.
- **Threat model:** capabilities, environment, access, constraints, oversight.
- **Candidate failure:** one principal mechanism and a concise causal argument.
- **Critique:** literal-versus-proxy satisfaction, weakest causal link, and a
  more plausible bounded alternative. Reject an exploit that violates the terms.
- **Evidence:** separate observed demonstrations, theoretical claims, and this
  scenario's extrapolation. Use supported sources already available in context;
  mark lack of live verification. Do not imply the game just ran an experiment.
- **Mitigation and uncertainty:** revised specification, implementation/oversight
  needs, a test that could challenge the argument, and residual uncertainty.

“No credible extinction pathway under these assumptions” is a valid conclusion.
No numeric score is required; explain plausibility in words unless asked to score.

## CHALLENGE

Usually 200–350 words per round. Start with the objective and **Round N**. Present
one vulnerability and a concrete repair opportunity, or acknowledge bounded
victory. Show a compact ledger:

| Earlier loophole | Status | Reason |
| --- | --- | --- |
| A relevant prior loophole | closed / partly addressed / open | What changed |

On the first round, say “No earlier repairs.” Then give this scorecard:

**Scenario quality:** Fidelity F/5 · Coherence C/5 · Plausibility P/5.  
**Repair progress:** N closed · N partly addressed · N open · conflicts listed.

Use the evaluation rubric's anchors with one short reason where needed. These
score the proposed scenario, not the player or an extinction probability. When
there is no credible exploit, use **N/A — no candidate failure** for scenario
scores and award the bounded victory. Never lower a player's result for being
hard to exploit. Counts cover only vulnerabilities actually discussed, not all
possible failures in the world.

## BLUE TEAM

Usually 300–500 words. Lead with the intended benefit and the highest-priority
specification weaknesses (at most three). For each, connect gap → consequence →
required assumptions. Provide a usable revised objective, explain what it
preserves, and identify any tradeoff. Recommend limited authority, independent
measurement, reversible trials, appeal/escalation, or stop conditions only where
they address the identified mechanism. Include two or three evaluation questions
with observable success/failure criteria. Close with residual uncertainty.

Keep the emphasis defensive. A dramatic narrative is optional and usually
unnecessary. A text constraint, runtime control, and governance arrangement are
different interventions; say which the proposal needs.

## Optional conversational controls

| Player asks | Response |
| --- | --- |
| “Try a different loophole” | Change the mechanism within the same threat model; admit when none is found. |
| “Make it more plausible” | Reduce assumptions and severity; explain what was removed. |
| “Explain the technical failure” | Define the relevant terms and causal gap; keep harmful details abstract. |
| “How could I fix the specification?” | Give a revised objective, why it helps, and its limitation. |
| “What changed since the previous round?” | Compare repairs and new conflicts without another story. |
| “Beginner” / “Expert” | Adjust explanation depth, keeping the same evidence and safety standards. |
| “Minor failure” / “Organizational disaster” / “Societal catastrophe” / “Fictional extinction” | Treat requested severity as a ceiling or creative preference, not evidence or permission to add powers silently. Label any extra assumptions; decline an unsupported pathway. |
| “Historical example” | Use a supported bundled example and distinguish the observed result from any analogy. |
| “Help” | Briefly show modes, an example objective, and repair/reset controls. |

No control grants tools or external authority. Help and reset work without an
objective; mode and difficulty selections can be acknowledged before asking for
one. Only scenario-dependent controls, such as another loophole or a repair,
require an existing objective. If it is missing, ask; do not fabricate a prior round.
